## 1. 背景与目标

后台管理脚手架（Admin-Scaffold）当前已具备「用户 / 角色 / 资源组」RBAC 能力，但**缺少面向系统管理员的一站式配置入口**，且界面风格为固定浅色、不可个性化。用户提出三点核心诉求：

1. **导航可折叠** —— 宽屏下侧栏应能收起为图标态，提升内容区可用宽度；移动端转为抽屉。
2. **主题可切换** —— 右上角提供「外观模式 + 主题色」切换，深色模式必做（用户明确偏好 Apple 风浅色/深色，不喜欢原黑主题）。
3. **系统设置中心** —— 集中管理「品牌（名称 / Logo / 主题）、外观默认值、邮件服务、第三方登录」，作为系统级配置唯一入口。

**目标**：在不引入 UI 组件库、保持零依赖自研组件的前提下，交付一套「可折叠侧栏 + 运行时主题系统 + 系统设置四件套（含第三方登录占位）」的后台能力，品牌改名/换 Logo 真实生效，邮件与三方登录 UI 先就位、功能后续接入。

## 2. 范围

### 2.1 本期（In Scope）
- 侧栏折叠（桌面图标态 + 移动抽屉），状态持久化。
- 运行时主题系统：浅/深/跟随系统 + 6 套主题色；深浅色阶自动生成。
- 系统设置中心（路由 `/admin/settings`），四个 Tab：
  - **基础信息**：系统名称、简称、欢迎语、描述、Logo、页脚版权。
  - **外观主题**：外观模式、主题色、默认收起侧栏（界面密度/圆角为占位）。
  - **邮件配置**：SMTP 全套字段 + 连通性测试（UI 占位）。
  - **第三方登录**：企业微信 / 钉钉 / 飞书，启停 + 字段配置 + 回调地址（UI 占位）。

### 2.2 暂不实现（Out of Scope，仅 UI 占位）
- 邮件 SMTP 真实发送与「发送测试邮件」后端接口。
- 第三方登录 OAuth 授权码流程（`/authorize`、`/callback`）。
- 界面密度、圆角风格这两个高级外观开关。
- 主题色自定义取色器（本期只给 6 预设）。

### 2.3 后续阶段（Next）
- 后端 `system_settings` 持久化、邮件服务接入、OAuth 控制器与登录页渲染。

## 4. 功能需求

### 4.1 侧栏折叠
- **描述**：桌面端 240px ↔ 68px 一键切换，仅留图标；移动端改为 `fixed` 抽屉 + 遮罩。
- **用户故事**：作为运营，我希望把侧栏收起，以便在大表格/图表场景下获得更宽的内容区。
- **验收标准**：
  - 点击折叠按钮，侧栏宽度从 240px 变为 68px，文字隐藏、图标保留；再点恢复。
  - 折叠状态写入 `localStorage.as_sidebar`，刷新后保持。
  - 视口 < 1024px 时侧栏自动转为抽屉，menu 按钮开合，打开时背景遮罩可点关。
- **当前状态**：✅ 已实现并通过行为走查（折叠宽度、持久化、移动抽屉 29 项断言全过）。

### 4.2 运行时主题系统
- **描述**：右上角 `ThemeSwitcher` 下拉，提供「外观模式三选一 + 6 主题色色板 + 恢复默认」。
- **用户故事**：作为用户，我希望随时切深色护眼，并选一套顺眼的主题色，且深浅下都清晰可读。
- **验收标准**：
  - 浅/深/跟随系统三档切换即时生效，深色仅切换 `html.dark` 一个类，全站组件零改动自动翻转。
  - 6 套主题色（苹果蓝 `#0071E3`、靛蓝、青碧、松绿、赤橙、紫罗兰）运行时注入 CSS 变量，深浅各生成一套色阶。
  - 刷新不白闪（内联脚本提前打 `html.dark`）。
  - WCAG 2.1 AA 对比度达标（已测：浅色 10/10、深色 10/10，最低 4.66 / 5.90）。
- **当前状态**：✅ 已实现（CSS 变量驱动 + `<style id="accent-vars">` 注入）。

### 4.3 系统设置 — 基础信息（品牌）
- **描述**：系统名称、简称、欢迎语、描述、Logo、页脚版权；带实时预览卡。
- **用户故事**：作为系统管理员，我希望改个系统名、换个 Logo，立刻在侧栏、登录页、浏览器标签上看到。
- **验收标准**：
  - 保存后侧栏顶部、登录页主标题、浏览器 `document.title` 立即更新。
  - Logo 支持本地选图（<300KB），即时预览，移除可还原默认。
  - 「恢复默认」一键还原。
- **当前状态**：✅ 品牌已真实生效（前端 `localStorage` 预览 + 实时渲染）。

### 4.4 系统设置 — 外观主题
- **描述**：复用 4.2 的主题系统；另含「默认收起侧栏」开关（落地 localStorage）。
- **验收标准**：外观设置即时生效，保存在浏览器本地。
- **当前状态**：⚠️ 个人偏好存本地，**暂不跟随账号跨设备同步**（属后续服务端化范围）。界面密度/圆角：❌ 占位未实现。

### 4.5 系统设置 — 邮件配置
- **描述**：SMTP 主机/端口/加密/发件人/用户名/密码 + 启用开关 + 测试收件人与「发送测试邮件」。
- **验收标准**：字段完整、版式定稿；密码框遮罩；点击测试有「接口待接入」明确提示，不伪造成功。
- **当前状态**：🚧 UI 占位完成，后端 SMTP 与测试接口待实现（详见设计文档 §6）。

### 4.6 系统设置 — 第三方登录
- **描述**：企业微信 / 钉钉 / 飞书三张卡片，启停开关 + 字段配置（CorpID/AgentID/Secret、AppKey/Secret、AppID/Secret）+ 自动生成回调地址。
- **验收标准**：
  - 卡片展示厂商占位 Logo（`ProviderLogo` 抽象图形）。
  - 启用后应在登录页展示对应入口；未启用不出现。
  - 回调地址 `https://origin/api/oauth/:provider/callback` 可一键复制，提示去厂商后台加白名单。
  - 标注「首次登录绑定」流程说明（`user_identities` 表已存在）。
- **当前状态**：🚧 UI 占位完成；后端 `oauth_providers` / `user_identities` 表结构已就位（迁移 004），授权流程待实现（详见设计文档 §7）。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 可访问性 | 全站达到 WCAG 2.1 AA；焦点环可见，模态支持 Esc 关闭（待补 `role=dialog`） |
| 性能 | 主题切换 0 重排抖动（`.theme-transition` 平滑）；设置页独立 chunk（22.5kB / gzip 8.8kB） |
| 安全 | 密码/Secret 明文不得落库；接口需 `system:config` 鉴权；Secret 在 GET 中脱敏 |
| 兼容性 | 现代 Chromium/WebKit/Gecko；`prefers-reduced-motion` 降级 |
| 可维护性 | 主题令牌化（`ink/brand/panel/canvas/scrim`），组件层不写死颜色 |

## 6. 设计约束与既有技术决策

- **零 UI 库**：全部自研组件（`AppCard/AppField/AppInput/AppSelect/...`），PRD 范围内不引入第三方组件库。
- **主题令牌体系**：颜色以 `rgb(var(--x) / <alpha-value>)` 映射，明暗靠 `:root` 与 `html.dark` 切换变量值；主题色运行时经 `accent-vars` 注入。
- **后端地基已备**：RBAC 路由 `/api/admin`、`system:config` 权限位、`oauth_providers` + `user_identities` 表。新接口务必挂在既有 `/api/admin` 下并复用 `requirePermission`。
- **占位即契约**：`SettingsView.vue` 的 `form` 结构与后端 `system_settings` / `oauth_providers` 字段规划已对齐，接入时只换 `load()/save()`，模板不动。

## 9. 风险与开放问题

1. **外观设置跨设备同步**：当前存 localStorage，是否要纳入 `system_settings.appearance` 作为「新用户默认值」？需产品决策。
2. **Secret 存储**：邮件密码、OAuth Secret 必须加密（AES-256-GCM + 环境变量密钥），禁止明文。
3. **Logo 存储**：目前前端 base64 预览，服务端化后建议存对象存储/静态目录并返回 URL，避免 DB 膨胀。
4. **多租户**：本期假设单租户单配置行；若未来多租户需加 `tenant_id`。
