## 二、关键设计决策（以及为什么不能更简单）

### 1. 主题令牌全面 CSS 变量化（本次最重要的地基）
全站有 **145 处 `ink-*` 工具类**。如果按常规做法给每处补 `dark:` 变体，既改不完也必然漏。
改为「`ink` / `brand` / `hairline` / `sidebar` 全部映射到 CSS 变量」，`html.dark` 只切换变量值 —— 组件层**零改动**自动翻转。

```js
// tailwind.config.js
ink: { 900: 'rgb(var(--ink-900) / <alpha-value>)' }
```
> 用「R G B 通道」而非整色存变量，`<alpha-value>` 占位才能让 `bg-brand-500/10` 这类透明度修饰符继续生效。

### 2. 主题色必须运行时注入，且要出「明暗两套色阶」
编译期写死的 hex 无法运行时替换，所以 `useTheme` 把色阶注入 `<style id="accent-vars">`。
更重要的是——**同一套色阶在明暗下需求相反**：
- 浅色模式：`brand-50` 要很浅（当选中项底色）
- 深色模式：`brand-50` 必须压暗（否则在深底上发白刺眼），而 `brand-600` 反而要**提亮**（按钮才有发光感）

因此按「往白混 / 往黑混」生成两套 ramp，而不是复用一套。

### 3. `scrim` 专用令牌（预防一个必然踩的坑）
模态遮罩原本是 `bg-ink-900/40`。暗色模式下 `ink-900` 是**浅色文字色**，拿它当遮罩会变成**白幕**——语义反转。
新增 `scrim` 令牌（明暗两种模式下都偏暗），修掉这个隐患。

### 4. `bg-white` → `bg-panel` 令牌
19 处 `bg-white` 若不动，暗色下卡片/模态/顶栏会是刺眼白板。统一换成 `panel` 令牌。

### 5. 防暗色首屏白闪
`index.html` 内联脚本在 CSS/JS 加载前先打上 `html.dark`；`main.js` 在 `mount()` 前 `initTheme()` 同步状态。

### 6. 品牌信息「本地预览」而非纯摆设
`useBrand`（localStorage）让系统设置里的**改名、换 Logo 真的立刻生效**：侧栏、登录页、浏览器标题同步变化。
接口未接入的部分（邮件、第三方登录）**不伪造保存成功**，页面明确标注「UI 占位 / 待接入」。

## 五、走查发现并修掉的问题

1. **`AppSelect` 值串化隐患（真问题，写代码时发现）**
   初版用 `:value` + `$event.target.value`，会把 `null` 变成字符串 `"null"`。这会直接导致用户管理里「不分配角色」被当成有效 ID 提交（`Number("null") → NaN`）。
   改为 Vue 的 `v-model` + option `_value` 往返语义，非字符串值才能原样透传。

2. **证据链瑕疵：`02-home.png` 与 `03-users.png` 字节完全相同**
   字节数一致暴露了问题——登录落地页是「第一个可见后台菜单」（`/admin/users`），所以「首页」截的其实是用户页，营销首页从未被截到。
   改为显式访问 `/` 后两者哈希已不同。

3. 折叠态「soon」占位项小圆点缺 `relative` 定位 → 已修。

4. 一次 `Edit` 误伤 `AppDropdown` 的 props 定义（替换串写窄了）→ 已修回，构建通过。
